## 上游调研：Wails v3 / Tauri v2 的 MSI 与代码签名（19:00）

**代码签名：两家都有，本质都是调 signtool**
- Tauri v2：`bundle.windows.certificateThumbprint` + `digestAlgorithm` + `timestampUrl` +
  `tsp`(RFC3161) + `signCommand`(%1 占位，转 HSM/Azure KV/osslsigncode)；
  `WINDOWS_CERTIFICATE`(base64 PFX) + `WINDOWS_CERTIFICATE_PASSWORD` + `TAURI_WINDOWS_SIGNTOOL_PATH`
- Wails v3：`wails3 sign` / `task windows:sign(:installer)`；SIGN_CERTIFICATE / SIGN_THUMBPRINT /
  TIMESTAMP_SERVER；密码进系统钥匙串（WAILS_WINDOWS_CERT_PASSWORD 给 CI）；
  额外有「内置跨平台签名后端」→ 非 Windows 主机也能签 Windows exe

**MSI：只有 Tauri 有，Wails v3 没有**（Wails = NSIS + MSIX，MSIX 需 makeappx/Windows SDK）
- Tauri MSI 走 WiX v3，关键：**自动下载 WiX 到 cache_dir/tauri/WixTools**（SHA256 校验），
  可用 `wix.toolsetPath` / `build.cacheDir` 指本地；仅 Windows 主机可构建；开销 ~2MB

**实验结论（更正上一轮判断）**：本机无 signtool、无 Windows Kits，但有 .NET 的
Set-AuthenticodeSignature / New-SelfSignedCertificate / Get-AuthenticodeSignature。
自签名证书 → 签名 zig-out/bin/zilt-app.exe 副本 → 结果：
`Status=UnknownError(自签名根不受信) / SignatureType=Authenticode / signer=CN=Zilt Test Signing /
alg=sha256RSA / 文件增长 1424B（证书表追加）`。即「Authenticode 签名产物有效性」可在本机验证，
不需要 CA 证书、不需要 Windows SDK。**仍未验证**的是 codesign.zig 构造的 signtool 命令行本身
（缺 signtool 可执行文件）。

## 多 WebView 数据分区完成（commit cfab660）

- **API**：`webviews.create({partition:'name'})` → 独立 Environment + UDF
  `<profile>\WebView2-partitions\<name>`；同名分区复用；`webviews.eval(id, script)` 异步
- **两个致命坑**（都实测蹦过）：
  1. 在 WebMessageReceived 回调里直接 `ExecuteScript` → WebView2 重入 segfault
     （EmbeddedBrowserWebView.dll）。必须 `WM_ZILT_EVAL` marshal 到消息循环再执行
  2. `emitJsonUi(msg)` **接管所有权并 free**，回调里再 `defer a.free(msg)` = double free
     → 崩溃栈落在 memsetSmallPow2/free（compiler_rt），不是业务代码，容易被误判
- 另：extern struct 不能放 slice/Allocator（COM 对象）→ 用 ptr+len / *const Allocator
- 测试：冒烟 c-partition 用同 origin 探针页读写 localStorage；**probe key 必须每次唯一**
  （分区数据跨运行持久化，固定 key 会让第二轮误判为「未隔离」）
- 单测 234（框架 216 + 工具 18）、冒烟 32 项连跑两次 exit 0、driver 4/4
