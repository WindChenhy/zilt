## 1. 背景与目标

### 1.1 现状（v0.1.24）

- 仅 Windows：`src/zilt/platform/` 下只有 `windows/`，`root.zig::run` 对非 Windows 直接 `@compileError`。
- 平台无关层已厚：`ipc` / `security` / `fs_api` / `protocol` / `net` / `sql` / `store` / `updater`
  / `patch` / `pack_formats` / `bindings` / `mcp` / `webview`（能力描述）与 89 个 Zig 文件里的
  大部分逻辑都不依赖 Win32。
- 验证基线：单测全绿；GUI 冒烟 49 项（`ZILT_SMOKE_EXIT=1`）；headless `/zilt/*` + `/mcp`；WebDriver。

### 1.2 为什么 v0.2 做 Linux

Tauri 2 与 Wails 3 都把 Linux 列为一等平台（amd64 + arm64）。Zilt 当前"Windows 100%、其余 0%"，
在框架选型表里这是最硬的一条短板；而 Linux 侧的技术路径（GTK + WebKitGTK）与现有抽象层契合度最高。

### 1.3 目标

1. 在 Linux（X11 优先，Wayland 可用）上跑通与 Windows 同构的能力面：窗口 / WebView / IPC /
   资产、协议 / fs / SQL / 网络 / 系统集成 / 打包。
2. 抽出**平台后端接口**，使 Windows / Linux 共用同一份 `Config`、`commands`、`events`、
   capability ACL 与前端运行时——应用代码零改动跨平台。
3. 建立 Linux CI（Xvfb + WebKitWebDriver），并保持 Windows 基线不回归。

### 1.4 非目标

- macOS（v0.3 及以后）、移动端。
- 自绘控件、自研渲染引擎、GTK 主题深度定制。
- 与 Tauri/Wails 的 ABI 兼容（只对齐能力面，不对齐 API）。

### 1.5 成功标准（v0.2 退出条件）

| 指标 | 目标 |
|---|---|
| 功能面 | Windows 已实现能力中，可跨平台的 ≥ 90% 在 Linux 可用 |
| 冒烟 | Ubuntu 22.04 + Xvfb 下 ≥ 40 项检查通过，退出码 0 |
| 单测 | 平台无关层单测两平台共用且全绿；Linux 平台层新增 ≥ 25 项 |
| 产物 | `.deb` / `.rpm` / `.AppImage` 可安装运行；`.desktop` 与图标正确 |
| 回归 | Windows 冒烟 49 项保持 exit 0 |
| 文档 | README 平台矩阵、ROADMAP 版本记录、ARCHITECTURE 平台层章节更新 |

## 3. 技术选型

### 3.1 GTK 版本：默认 GTK3 + WebKit2GTK 4.1

- **覆盖率**：Ubuntu 22.04、Debian 12、RHEL 9、openSUSE Leap 等 LTS 只提供 `webkit2gtk-4.1`；
  WebKitGTK 6.0 需 Ubuntu 24.04+/Debian 13+。
- **风险**：GTK3 的 WebKit 端口在 120Hz 屏上滚动被限制在 60fps（WebKitGTK 社区已知；GTK4 端口 120fps）。
  接受该折衷，v0.2.5 提供 GTK4 变体（`-Dgtk=gtk4`）供新发行版使用。
- **实现方式**：平台层用 `build.zig` 选项切换 pkg-config 包名与少量 API
  （`gtk_clipboard_*` vs `gdk_clipboard_*`、`GtkFileChooserNative` 两者皆可），
  业务逻辑（backend 状态机）保持单份，差异收敛在 `gtk_compat.zig`。

### 3.2 绑定方式：`@cImport` + pkg-config（不引第三方 GObject 绑定）

- GTK/WebKitGTK 是稳定的 **C ABI**，`@cImport(@cInclude("gtk/gtk.h"))` 即可拿到全部类型/常量；
  信号回调用 `g_signal_connect` + `callconv(.c)` 的 Zig 函数，不需要 GObject 类继承。
- 相比 Windows 的手写 COM vtable，Linux 侧工作量显著更低（无 IID/vtable 手工布局）。
- `build.zig`：`exe.linkSystemLibrary("gtk-3")`、`linkSystemLibrary("webkit2gtk-4.1")`，
  用 `b.addSystemIncludePath` + pkg-config 提供的 cflags/ldflags（`std.Build` 的
  `linkSystemLibrary` 会走 pkg-config）。
- **已就位（v0.2.0）**：`build.zig` 用 `target.result.os.tag` 做平台裁剪——
  Win32 六库（user32/gdi32/ole32/advapi32/comdlg32/shell32）、图标资源、`subsystem = .windows`
  与 Windows 专用工具（cli/driver/dev/bundle/keygen/sign/diff/pack/init）只在 Windows 上生效；
  非 Windows 上这些 step 保留名字但执行即给原因（`windowsOnlyStep`），
  `frontend.build_command` 改走 `sh -c`。因此 Linux `zig build` 现在能一路走到
  `platform/linux/backend.zig` 的「后端未实现」报错，而不是卡在 `-lshell32`。
- 约束：`@cImport` 要求目标机有开发头文件；发布产物不依赖头文件。CI 装 `libgtk-3-dev`、`libwebkit2gtk-4.1-dev`。

### 3.3 事件循环与线程封送

- UI 线程 = GLib main loop（`g_application_run`）。
- worker（http / ws / fs watch / process）→ UI：`g_idle_add(callback, ctx)`（线程安全入队），
  对应 Windows 的 `PostMessageW(WM_ZILT_*)`。
- UI → JS：`webkit_web_view_evaluate_javascript`（异步，带 callback）；
  JS → UI：`webkit_user_content_manager_register_script_message_handler("zilt")` +
  `script-message-received::zilt` 信号。
- 重入约束与 Windows 一致：回调内不做会再次触发 WebKit 同步回调的操作，必要时 `g_idle_add` 延后。

### 3.4 网络：libsoup 3（不新增依赖）

- WebKitGTK 4.1 已依赖 libsoup3，直接复用做 `http` / `ws` / `wss`：
  `SoupSession` + `SoupMessage`（HTTP/2、TLS、代理、重定向）；`SoupWebsocketConnection` 做 WebSocket。
- 好处：与 WebView 共享 TLS 信任链/代理配置，行为一致；避免 libcurl 的额外链接与证书库差异。
- 保留现有 `http`/`ws` 的 JS API 与事件名（`httpResponse` / `httpChunk` / `wsEvent`），仅换后端实现。

### 3.5 测试：Xvfb + WebKitWebDriver

- 冒烟：`xvfb-run -a ./zig-out/bin/zilt-app --smoke`，前端检查表复用（49 项中与平台无关的 ≥ 40 项）。
- E2E：`webkit2gtk-driver`（WebKitWebDriver）暴露 W3C WebDriver；`zilt-driver` 增加 Linux 会话
  （`POST /session` 的 capabilities 用 `browserName: MiniBrowser`/`webkitgtk`）。
- CI：GitHub Actions `ubuntu-22.04` 容器 + `xvfb`，先跑 Windows 任务再跑 Linux，互不阻塞。

## 4. 架构设计

### 4.1 平台抽象层

新增 `src/zilt/platform/backend.zig`（接口描述，非 vtable）：

```
run(comptime config)                      // 入口
createWindow(opts) -> WindowId
closeWindow(id) / windowQuery(id)
beginChildWebview(id, opts) / childEval(id, js)
postMessageToJs(id, json)
setMenu(id, MenuModel) / tray(op) / notify(op)
clipboardRead/Write / dialogs / fs ops / http / ws / process
```

- 现状是 Windows backend 直接实现 `run(config)`，其余能力通过 `ipc.Context` 的函数指针注入
  （`clipboard_*_fn`、`webview_request_fn`、`spawn_window_fn`…）。这一层已经等价于接口，
  v0.2.0 只需要**把 `ipc.Context` 的构造收敛到 `platform/<os>/context.zig`**，避免 Windows 代码里
  重复拼接。
- `shared` 模块（ipc / security / fs_api / protocol / net 解析 / sql / store / patch / pack_formats）
  零改动，直接被两个后端引用。

### 4.2 目录

```
src/zilt/platform/
├── windows/            # 现状
└── linux/
    ├── backend.zig     # run / 窗口生命周期 / 事件循环
    ├── gtk.zig         # @cImport 封装 + 信号连接辅助
    ├── webkit.zig      # WebKitWebView / UserContentManager / Scheme / Settings
    ├── window.zig      # GtkApplicationWindow + HeaderBar + 尺寸/位置/透明
    ├── assets.zig      # zilt:// scheme handler（复用 asset_routes）
    ├── ipc_bridge.zig  # 脚本消息 ↔ ipc.dispatch
    ├── tray.zig        # libayatana-appindicator（可缺省）
    ├── notify.zig      # GNotification
    ├── dialogs.zig     # GtkFileChooserNative / 颜色 / 字体
    ├── dnd.zig         # GdkDragAndDrop + 文件列表
    ├── fs_watch.zig    # inotify
    ├── hotkey.zig      # X11 XGrabKey / portal GlobalShortcuts
    ├── single.zig      # GApplication 唯一 ID + 命令行转交
    ├── autostart.zig   # ~/.config/autostart/*.desktop
    ├── sysinfo.zig     # /proc + gdk monitors + /etc/os-release
    └── pack.zig        # .desktop / AppImage AppRun / Flatpak manifest
```

### 4.3 资产与协议

- Linux 上 `Config.protocols` 可以直接注册**真 scheme**（`webkit_web_context_register_uri_scheme`）：
  `zilt://proto/<name>/<path>`，比 Windows 的 `/__proto/` 更贴近 Tauri。
- 内嵌资产同样走 scheme：`zilt://app/index.html`；为兼容现有前端代码，`https://zilt.app/...`
  通过 `webkit_uri_scheme_request` 的 host 判断等价映射（`config.url` 的 origin 保留）。
  **决定**：前端 base URL 不变，asset handler 里同时接受两种形式，避免模板改造。

### 4.4 窗口

- `GtkApplicationWindow` + `GtkHeaderBar`（decorations=true 时）；`titlebar_overlay` 对应
  `gtk_window_set_titlebar(null)` + 自绘拖动区。
- 透明：`gtk_widget_set_app_paintable(TRUE)` + RGBA visual + `screen` 的 alpha。
- 尺寸约束：`gtk_widget_set_size_request` + `gdk_window_set_geometry_hints`。
- 多显示器/HiDPI：`gdk_monitor_get_scale_factor`，坐标换算与 Windows 的 DPI 逻辑对齐。

### 4.5 打包

- `.desktop`：`[Desktop Entry]` + `MimeType=x-scheme-handler/zilt;<file-assoc>` + `StartupWMClass`。
- deb/rpm：复用 `pack_formats.zig`（已有 ar+tar.gz 与 spec 生成器），补 Linux 二进制与依赖声明
  （`libgtk-3-0`、`libwebkit2gtk-4.1-0`）。
- AppImage：AppDir + AppRun + `linuxdeploy` 可选；`pack.zig` 已能生成 `build-appimage.sh`，需实测。
- Flatpak：`manifest.json`（runtime `org.gnome.Platform`），v0.2.4 交付（不阻塞）。

## 6. 版本规划

### v0.2.0 —— 平台抽象 + Linux 骨架（M1）

- 抽出 `platform` 接口与 `ipc.Context` 构造收敛；Windows 后端改为实现该接口（无行为变更）。
- Linux：`GtkApplication` + `GtkApplicationWindow` + `WebKitWebView`，加载内嵌资产（scheme）。
- IPC 桥（脚本消息 ↔ `ipc.dispatch`）、`window.zilt` 运行时注入、greet 命令往返。
- `zig build` 在 Linux 上用 pkg-config 正确链接；`zilt doctor` 增加 Linux 检查项。
- **验收**：Xvfb 下窗口起来、`greet` 返回、资产 200、单测全绿；Windows 冒烟 49 项不回归。

### v0.2.1 —— 窗口与 WebView 面（M2）

- 多窗口 / 父子 / 模态 / 全屏 / 置顶 / 最小最大；窗口状态持久化。
- eval（async）、devtools、缩放、前进后退、UA、下载、清存储、数据分区、截图。
- 子 WebView（同窗附加）——对齐 v0.1.16 的 `webviews.*` API。
- **验收**：Linux 冒烟 ≥ 20 项；多窗口与分区隔离 E2E。

#### v0.2.1 实施记录（Linux 侧，切片 1–3）

三个切片全部在 `src/zilt/platform/linux/` 内完成（平台无关层零改动）：

- **切片 1（3c330b9）窗口 API**：`window_fn` / `window_query_fn` 全套基础动作
  （set_title/minimize/maximize/restore/fullscreen(_monitor)/size/position/show/
  hide/focus/close/start_dragging/always_on_top(_bottom)/skip_taskbar/focusable/
  enabled/theme(dark)/limits(geometry hints)）；未实现项（光标系列/穿透/截图保护/
  阴影/图标）返回 false，错误语义与 Windows 对齐。
- **切片 2（761d165）WebView 面**：`webview_request_fn`（reload/stop/back/forward/
  zoom/get_zoom/history/devtools/set_user_agent/eval）+ `eval_async_fn`；
  eval 双路径——异步（completion 回调）与同步（嵌套 GMainLoop，对应 Windows 的
  SyncWait 局部消息泵）；print/cdp/cookies/clear_storage 返回 NotSupported。
- **切片 3（本切片）多窗口 + 子 WebView + 数据分区**：
  - **窗口注册表**：每窗口独立 GtkWindow/WebView/UCM/脚本/状态跟踪，id 从 1 起
    （主窗口固定 1）；`window_fn`/`window_query_fn`/`webview_request_fn`/
    `eval_async_fn`/`emitEntry`/ACL 的 source+label 全部按 window_id 路由
    （0 → 主窗口，对齐 Windows 的 `windowById(if (id == 0) 1 else id)`）。
  - **`spawn_window_fn`**：title/size/position/visible/resizable/decorations/
    always_on_top/skip_taskbar/limits 映射 GTK 属性；parent/modal →
    `gtk_window_set_transient_for` + `gtk_window_set_modal`（父销毁级联关子窗口，
    注册表维护父子关系）；child（Win32 WS_CHILD 概念）、per-window proxy/icon/
    background_color/user_agent/titlebar_overlay 无 GTK 直接对应物，显式忽略。
    Linux 的 dispatch（script-message 信号）本身在 UI 线程，无需 Windows 的
    WM_ZILT_NEWWIN 封送。
  - **退出语义**：所有窗口都销毁才 `gtk_main_quit`（对齐 Windows「全部关闭才退出
    消息泵」），主窗口销毁不再直接退出。
  - **`system_fn`**：接通 `.webviews` op（create/remove/navigate/setBounds/focus/
    list/eval）；其余 op 返回 NotSupported（`platform/interface.zig` 降级契约不受

**踩坑记录（切片 3–4 实测）**：

1. **WSLg 下必须 `GDK_BACKEND=x11`**：WSL 会话默认 `WAYLAND_DISPLAY=wayland-0`，

   前提一致）。
2. **GtkFixed 会把子控件 size_request 变成窗口最小尺寸**：主 WebView 放进
   GtkFixed 后 `gtk_window_resize(800,600)` 被钳制在初始 960x700（冒烟 win.size
   失败）。改用 GtkOverlay：主 WebView 作为 main child 自动伸缩，子 WebView 用

3. **WebKitUserScript 不是 GObject**：`g_object_unref` 会打 GLib-CRITICAL，
   必须用 `webkit_user_script_unref`。
4. **本 WebKit2GTK 头文件（Ubuntu 22.04, 2.50.4）没有
   `webkit_web_view_new_with_user_content_manager_and_context`**：分区子 WebView
   用 `webkit_web_view_new_with_context` + view 自带的
   `webkit_web_view_get_user_content_manager`（注册 handler / 注入脚本等效）。
5. **子 WebView eval 的就绪判定不能只看 `document.readyState`**：create 后页面
   还停在 about:blank，其 readyState 立即就是 complete，localStorage 在 opaque
   origin 上会抛 SecurityError。settle 需同时等 `location.pathname` 到达目标页。
6. **跨页面 localStorage 传播非即时**：子页面写入后主页面立即读会拿到旧内存
   缓存（null）；等 ~300ms 传播后一致（反向主→子同样成立）。
7. **下载失败后 WebKit 还会补发 `finished`**：只在失败回调里 `removeDownload`
   会让第二个回调拿到已释放的 `user_data`（实测出现天文数字 id 的 completed）。
   终止事件里先把 received-data/finished/failed 三个 handler 全部
   `g_signal_handler_disconnect` 再释放记录。
8. **destroy 信号里 `gtk_window_get_size/get_position` 会退化到创建时的默认值**：
   直接查询保存会把用户/程序调整后的几何丢掉（实测存成 0,0 + 初始尺寸）。
   状态保存必须用 `configure-event` 跟踪值，并在 `window_fn` 的 size/position
   命令里同步更新（Xvfb 无 WM 时 configure 也可能不来）。
9. **`zilt://` 自定义 scheme 不能下载**（WebKit 报 `The URL can't be shown`），
   冒烟改用 `data:` URL；data: 的 suggested filename 为空 → 走 `download-<id>`
   兜底命名（重名再追加 `" (n)"`）。
10. **固定 label 会被 `persist_window_state` 恢复上一轮几何**：冒烟里第二窗口
    第一次跑保存了 440x340，第二次创建的 420x320 被恢复成 440x340（框架行为正确）。
    多窗口/状态类断言用唯一 label（`smoke-second-<ts>`）隔离。
11. **`GdkEvent` 在 translate-c 里是不透明 union**：`configure-event` 回调参数
    只能声明为 `?*anyopaque`，再转 `[*c]c.GdkEventConfigure` 读 x/y/width/height。

  封送 → `fsEvent {id, action, path}`；被监视目录自身被删（DELETE_SELF）→
  上报 removed 后自停。
- **fs 流式读**：一次性读入（32MB 上限）+ 按 chunk 切片 → `fsChunk
  {id, seq, done, data(base64)}`（0.17 的 Io.File 流式读面向 reader 接口，
  内存分片足够）。
- **SQL**：`sqlite.zig`（libsqlite3 dlopen：ZILT_SQLITE_PATH → libsqlite3.so.0
  → libsqlite3.so）——API 表/行集 JSON/事务迁移与 Windows 版逐行同构。
- **http/ws（libsoup3）**：每请求一个 SoupSession（对齐 WinHTTP 的 per-request
  会话），`timeout/idle-timeout` 从 timeout_ms 推导；proxy 走
  `g_simple_proxy_resolver`；`insecure_tls` 挂 accept-certificate 信号；
  `follow_redirects:false` → SoupMessage:follow-redirects 属性（best-effort）；
  multipart 复用共享 `net.buildMultipart`。响应体 64KB 分块
  `g_input_stream_read_bytes_async` 读：stream 模式逐块 `httpChunk
  {id,seq,data(base64)}`、普通模式累积后 `httpResponse {id,status,body,err?}`。
  WebSocket：`soup_session_websocket_connect_async` + message/closed/error
  信号 → `wsEvent {id,kind,data?,binary?,err?}`；send 文本优先（非法 UTF-8
  转二进制）。
- **protocols → 真 scheme**：每协议注册同名 scheme（`echo://a/b?x=1` 对应
  Windows 的 `/__proto/echo/a/b?x=1`）；`webkit_uri_scheme_request` 的
  http_method/http_headers（2.36+）供 handler 的 method/user_agent；响应带
  ACAO + Expose-Headers（自定义 scheme 的 fetch 受 CORS 约束，Tauri 同款）；
  CSP/security.headers 继续叠加（applySecurityHeadersRaw）。

**踩坑记录（v0.2.3 实测）**：

1. **0.17 的 `std.Thread.spawn` 栈参数**：glibc 对 <384KB 的栈返回 EINVAL，
   0.17 把它映射成 `unreachable` → **panic 而非错误**——必须用现成的
   `sys.threadStackSize`（项目在 Windows 更新器时代就沉淀了这个助手）。
2. **GError 消息的生命周期**：`g_error_free` 之后 message 指针失效——
   先 dupe 再 free，否则 JSON 序列化读到脏内存（实测 http/ws 错误载荷变字节数组）。
3. **`webkit_uri_scheme_response_set_http_headers` 转移所有权**（transfer
   full）——之后再 unref 会在响应写回时 SIGABRT（实测 134）。
4. **libsoup3 头/方法参数都要 NUL 结尾副本**：JS 传来的 `method` 是
   非哨兵 slice，直接 `.ptr` 会让 soup 读越界（实测 echo 服务器回 501）。
5. **`[*c]OpaqueType` 禁用**（0.17）：SoupMessage/SoupWebsocketConnection/
   SoupMessageHeaders/GdkDragContext 等全部用 `?*c.T` 单指针。
6. **0.17 API 漂移清单**（本轮踩到）：`std.fs.cwd()`/`std.fs.openFileAbsolute`/
   `std.Thread.Mutex`/`std.crypto.random`/`std.time.nanoTimestamp` 均移除——
   分别改 `std.Io.Dir`（openDir/iterate/renameAbsolute/statFile，iterator 的
   next 要传 io）、`g_get_real_time`；`Io.Dir.rename` 是
   (old_dir, old, new_dir, new, io) 五参——跨目录用 renameAbsolute。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| GTK3 WebKit 60fps 上限 | 高刷体验差 | v0.2.5 提供 GTK4 变体；文档标注帧率差异 |
| pkg-config 依赖缺失导致构建失败 | 新用户流失 | `zilt doctor` 给出逐条 apt/dnf/pacman 命令；CI 固化镜像 |
| WebKitGTK 版本 API 差异（4.0/4.1/6.0） | 编译期/运行期不兼容 | 明确不支持 4.0；编译期 `#if WEBKIT_CHECK_VERSION` 分支 |
| 托盘依赖 libayatana 非默认安装 | 功能缺失 | 可选依赖 + 缺失降级（无托盘仍可运行） |
| Wayland 无全局快捷键 | 功能缺失 | X11 实现 + portal 方案；Wayland 下明确返回 `NotSupported` |
| GTK 主循环与 worker 线程错误封送 | 崩溃/竞态 | 统一 `g_idle_add` 封送；禁止在 worker 直接碰 GTK 对象 |
| 交叉编译不可行 | 发布流程复杂 | 用容器/CI 原生构建（与 Tauri 一致） |
| 平台抽象抽取引入 Windows 回归 | 高 | v0.2.0 只做接口收敛、不改行为；Windows 冒烟每版必跑 |
