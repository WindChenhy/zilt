# ADR-0001：绑定自研——不依赖 webview/webview C++ 库与第三方 Zig 绑定

日期：2026-11-07 · 状态：已接受

## 背景

调研（docs/research/）指出两条起步路径：(a) PoC 复用 webview/webview（~7k 行 C++）快速验证；(b) 直接自研各平台绑定。第三方 Zig 绑定（happystraw/zig-webview、thechampagne/webview-zig）star 少且锁旧版 Zig。

## 决策

**直接自研全部平台绑定，不引入 webview/webview，不依赖第三方 Zig 绑定库。** 仅允许三个底层互操作库作为依赖：zigwin32（可选）、zig-objc（macOS）、zig-gobject（Linux）。

## 理由

1. 项目核心价值主张就是「纯 Zig 绑定」；引入 C++ 库违背目标且带来 C++ 工具链要求（webview 在 Windows 需 C++14）。
2. webview/webview 功能面不足（无多窗口、custom scheme 不可控、无打包），Phase 1 前必然脱离——早晚要写的东西直接写。
3. 自研绑定才能掌控 ABI 细节（自定义协议、IPC 语义），这是框架层差异化所在。
4. 绑定层目标体量小（wry 级别 ≈8k 行），可控。

## 后果

- PoC 阶段无法「几天出原型」，需按平台逐步落地（先 Windows）。
- 每 6 个月 Zig 版本迁移时绑定需同步维护（已列入风险清单）。
- 参考 docs/reference/ 的 ABI 笔记实现，避免凭记忆写 vtable。
